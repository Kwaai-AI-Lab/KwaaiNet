### Why that is the expected result

Every relation dream extracts is `associated_with`. Sampled across Pierre,
Prince Andrew, Napoleon, Kutuzov and Rostov in WarPeace: **31 of 31 relations
were `associated_with`**, with no typed relation of any kind. D6's typed
relations (`spouse_of`, `parent_of`, `sibling_of`) come from the YAML seed, not
from extraction.

An untyped edge can still help graph-anchored traversal, but it carries no
information about *how* two entities relate, and D6 retrieval is already carried
by hybrid BM25 + dense vectors. So adding thousands of generic edges moves the
recall number not at all.

Some edges are worse than uninformative. Pierre in WarPeace is linked to
`Whomhast` and `Russianforces` — tokenisation artifacts — and to `Saint Peter`,
which looks like name confusion. That is an extraction-quality problem upstream
of dream, the same class as D6's `Granny` and `Solly` typed as Organizations.

### What this means for the sweep

The run retains its value as a **native-p2p soak test** — 1440+ completions,
every one a unary call over `/kwaai/ollama-proxy/1.0.0`, with zero transport
failures. As *graph enrichment* its measured effect on retrieval is zero.

Two things would change that, neither of which is a compute problem:

- **A real relation vocabulary.** `associated_with` is the only type extraction
  produces. Typed relations are where graph retrieval earns its keep.
- **Entity hygiene before enrichment.** Enriching a graph that contains
  `Whomhast` spreads the artifact rather than fixing it.
